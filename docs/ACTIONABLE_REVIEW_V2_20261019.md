# Badcase 驱动优化 v2：核验动作、重复修订守卫与可修正假设

日期：2026-10-19。背景：[Badcase 归因](BADCASE_ATTRIBUTION_20261018.md)、[v1 实测](EVIDENCE_CONTROLLED_RESEARCH_20261018.md)。v1 的 4 题配对结果未证明准确率提升，Token 增加约 26.4%；因此 v2 不沿用“已证明有效”的结论，也不默认启用。

## 本次落实的两项改进

### 1. 结构化核验动作与重复修订守卫

新增 `ActionableVerdict`，核验意见包含类型、受影响的需求/claim、是否阻断以及处理动作：

| 类型 | 动作 | 是否阻断 |
|---|---|---|
| 必要证据缺失 | research 或 stop | 是 |
| 草稿与证据矛盾 | revise 或 stop | 是 |
| 引用错误 | revise 或 stop | 是 |
| 影响答案的证据冲突 | research 或 stop | 是 |
| 不影响答案的说明 | finish | 否 |

协议拒绝“冲突 + 不阻断”“冲突 + finish”等不一致组合。无法分类的旧 `issues`、越界目标、缺失覆盖、未通过的 claim、非法引用仍保持阻断，不自动降级为说明。最终是否属于真正的冲突仍由独立模型判断，类型约束不能证明其语义判断正确。

非阻断说明独立保存在 `review_notes`，不再触发无限修订；在生产答案中作为资料说明保留。必要关系、claim、引用及完整性检查全部通过后才允许结束。

重复修订采用保守的精确输入指纹，不使用语义相似度推断“没有进展”。指纹覆盖原问题、当前草稿、实际证据上下文、冻结需求、假设、策略、记忆上下文与可用的模型配置。相同输入再次进入核验时复用上一份结果；仍有阻断问题则以 `unchanged_review_input` 停止，保留不完整状态。引用编号错误的本地检查也受此守卫保护。

缓存和动作放在图状态中，可在相同策略的检查点恢复后继续使用。输入发生变化则重新核验。当前明确不对图像证据复用文本指纹结果。此缓存不声称识别同义改写：只是措辞不同但含义相同的草稿仍可能再次调用核验器，原有最多三次核验等上限继续生效。

### 2. 冻结用户要求，允许修正证据支持的解释假设

`requirements` 保留原问题要回答的属性与关系，不允许后续调度悄悄删除。实体类型、指代和中间解释放入单独的 `plan_assumptions`，初始为 `unconfirmed`，不能当作证据。

只有独立 Verifier 可以提出带引用、状态和原文引句的假设修正。代码检查引用是否属于实际授权上下文、引句是否逐字出现在对应证据中。重复键、无效引用或不存在的引句不能用于接受该修正。引句存在性只是来源检查，是否真正支持新解释仍是模型判断，不能等同事实真值。

接受修正后：记录原值、新值、引用与引句；清空旧支持状态及完整覆盖状态；重新研究/起草，再独立核验。父 Agent 不能靠修改自己的解释就沿用旧核验。修正后的简短假设会传给新的独立子任务，完整父消息历史仍不传入。

这针对 KABG 类案例：问某实体的所在地，不能直接把该实体当成城市名称。但并未证明真实模型已能正确拆解该题。

## 模块、版本和入口

- `agents/contracts.py`：可执行核验契约、解释假设和图状态字段。
- `agents/review_control.py`：仅依赖标准库的指纹、动作分类和引句来源检查。
- `agents/answering.py`：核验结果处理、缓存与假设修正。
- `agents/coordinator.py`：在既有预算、轮次与调度上限内选择定向检索、修订或结束。
- `agents/researcher.py`：将简短假设传入新子任务。
- 应用装配、配置和离线 CLI 均接入，生产不导入离线评测模块。

保留原 `mainline` 和 `mainline-evidence-controlled-v1` 的行为；新增两个可区分的方法：

| 方法 | 可执行核验与重复守卫 | 可修正假设 |
|---|---|---|
| `mainline-evidence-controlled-v2-reviews` | 开启 | 关闭 |
| `mainline-evidence-controlled-v2` | 开启 | 开启 |

生产配置新增版本选择，但默认开关和 v1 选择均未更改：

```dotenv
AGENT_EVIDENCE_CONTROL_ENABLED=false
AGENT_EVIDENCE_POLICY_VERSION=v1
```

测试 v2 时同时设置开关为 `true`、版本为 `v2`，以新运行验证。不要跨策略恢复旧检查点。未修改私有配置，也未重启现有服务。

离线评测沿用已有入口，将 `--method` 指定为上述方法，并保持与对照一致的 manifest、模型、语料和预算。不要覆盖旧输出或自动重试已保存的失败。

## 已验证范围

`tests/test_actionable_review.py` 新增 25 项测试，覆盖：

- 非阻断说明与真实冲突采用不同动作，未知旧意见不会被降级。
- 相同输入复用核验并终止重复修订；变化的草稿、证据等使指纹变化。
- 非法引用的重复修订也终止，图像证据不复用文本缓存。
- 只有合法来源引句的假设修正能被接受；修正后必须重新核验。
- 新独立子任务收到修正后的假设，冻结需求保持不变。
- 图检查点恢复后保留停止重复修订的状态。
- 原 mainline/v1 协议和流程兼容。

其中《The North Star》夹具来自上一轮真实运行的 Verifier 输入，保留输入来源哈希与事件索引。两种新的核验输出是显式脚本场景：保留冲突时继续核查；移除冲突来源、仅保留范围说明时允许结束。它们是机制回归，不是新的模型推理、人工标签或原案例重新评分。

完整后端测试与数据保护记录见 `output/actionable-review-20261019/validation.json`；完整日志为同目录 `pytest-final.log`。

本轮没有进行新的真实模型配对调用、没有改变 gold 或人工标签，因此不声称准确率、Token 或服务延迟已改善。后续应先分别比较 v1、v2-reviews 和 v2，并同时报告正确率、拒答率、重复核验、调用次数、Token 和缺失用量；本轮仍保留 v1 的两次工具检查间隔，尚未实现事件触发的自适应检查策略。
