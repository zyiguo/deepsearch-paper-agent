# 候选复用与空证据核验优化（v4）

## 行为与边界

v4 是显式启用的实验策略，v3 保留为同版本代码内的对照。配置选项为 `AGENT_EVIDENCE_CONTROL_ENABLED=true` 和 `AGENT_EVIDENCE_POLICY_VERSION=v4`；示例及实际生产默认未开启。

- **稳定身份**：生成器通过 `existing_candidate_id` 给已有候选补路径。服务端保留旧答案和解释，不能通过同一编号悄悄改写命题；新增路径仍交独立核验器审查原命题。未知编号拒收并留轨迹。
- **保守去重**：仅对答案与解释都一致（允许空白差异）的候选合并，对完全相同的路径去重。不同地点、同名实体、时间和角色解释仍保留；没有模糊相似度合并。
- **紧凑输入**：后续生成只接收候选编号、答案、解释、状态，不重复携带证书与旧核验文本。完整快照、原始提案和拒收原因留在轨迹。
- **空路径核验**：所有可提交路径都没有步骤时，直接记录未知，不调用语义核验器；按原问题要求继续检索。部分路径、缺引用或缺桥接事实的非空路径仍可接受独立核验，不当作已证实。
- **重复输入停止**：同一工作流内，问题、要求、证据快照、指令、答案类型、记忆、工作笔记、技能及客户端身份未变，且前次仍未解决时，不再次生成或核验，保留候选并停止重复循环。新证据或上下文变化会重新生成。恢复到新工作流时保守失效，避免复用旧环境判断。
- **资源与轨迹**：沿用四候选、三路径、三轮研究/评审的上限。跳过调用单独记录 `candidates.generation_skipped` / `candidates.verification_skipped`；`semantic_review_performed=false` 区分本地未知判断与模型核验。不能把少调用次数换算为声称已节省的真实 Token。

核心合并逻辑在 `core/candidate_reuse.py`，流程在 `agents/path_answering.py`，实验入口为 `scripts/evaluate_candidate_reuse.py`。生产代码不读取评测答案或 Badcase 标签。

## 对照协议

复用原四道开发集案例与语料，v3/v4 在相同冻结代码、模型、检索器和预算下各运行一次，不自动重试。模型为 MiMo v2.6 Pro；每题最多 24 次模型调用、8 次检索、256000 Token、600 秒，输出上限 8192，上下文 131072，top-k 为 5。

KABG 题沿用既有金标隔离：不能将新墨西哥州 Los Alamos 与加州同名城市拼接，因此有效正确率分母为另外三题。仍保留所有四题的原始答案、成本和轨迹。成功、失败、未知分开导出；模型执行完成与答案正确分别统计。

新结果存入 `output/candidate-reuse-20261019`；旧实验及原数据只读并核对校验和。主成本指标使用供应商实际报告的总 Token，缺失保持 null。四题单次随机结果只用于机制检查，不能推断稳定总体增益；候选编号未丢失也不等于语义误合并率为零。

### 机制证据与失败原因

KABG 的 v3 最后出现四个未知候选，包含重复改写；v4 三轮保留同一个候选编号，后两轮明确以原编号补路径，未知候选没有被驱逐。所有案例中，已有候选编号均保留。该观察验证了编号更新机制，不能代替独立的语义去重正确性标注。

但是 v4 在 KABG 中生成的是**非空但不能回答县名的路径**。引文确实存在，部分步骤却在解释“县名证据缺失”；独立核验仍判未知。后续检索改变了证据快照，未触发完全相同输入的停止条件。真实八次运行中，生成跳过和核验跳过均为 0；这些分支只有定向行为测试覆盖，不能声称已经贡献真实节省。

KABG 的生成角色 Token 从 16562 降到 15302，但核验从 14528 增到 22271。The North Star 的核验从 6319 增到 16364。两道题分别发生一次核验格式修复，额外调用及输出抵消了紧凑候选输入的潜在收益。随机生成差异同时存在，不能把全部成本差异归因于一个机制。

下一步应针对“已经独立确认的证据缺口”设计增量核验：明确保存缺少的要求及可补足它的新证据，避免把缺证说明包装成完整路径；对核验输出长度在生成提示与契约间保持一致。新增或可能推翻旧结论的证据仍须复核，不能仅凭证据相似度跳过。此方向尚未实现，本轮不把实验版设为生产默认。
