# 内容 ID 与多模态重排

## ID 契约

所有正文、OCR、图表、公式、原页图像和提问附件使用同一套字段：

| 字段 | 含义 |
| --- | --- |
| `content_id` | `cnt_` + SHA256 内容指纹；相同内容可跨来源共享 |
| `chunk_id` | `chk_` + SHA256 来源、位置、证据类型、内容；检索去重的持久标识 |
| `asset_ids` | `ast_` + SHA256 来源与页码；关联同一原页的不同证据表示 |
| `identity_version` | 当前为 1，标识哈希契约版本 |
| `citation_id` | 单次回答中的显示序号，不是持久 ID |

文字指纹只统一 Unicode NFC 与换行，不去除有意义的空白。图像指纹基于实际保存的规范 PNG 字节，不基于模型描述或占位文字；渲染或编码结果变化可能改变指纹。文字描述与原图是不同内容，通过 `asset_ids` 关联，不强行共用 `content_id`。

持久 ID 不包含 Embedding 模型名称，重建向量不改变片段身份。托管 PDF/图片 URI 的文件名不参与来源身份，重命名不改变 ID；普通路径仍是来源身份的一部分。不同文献里的相同文字保留不同 `chunk_id`，避免丢失引用来源。跨页片段关联所有覆盖页。回答预算裁剪只产生片段视图，保留原片段 ID。

## 索引与接口

索引快照升级为版本 4，保存和加载时校验 ID 与内容、来源、位置的一致性。旧版 1/2/3 快照仍可加载：文字 ID 本地补齐；旧图像 ID 在应用启动时读取原页补齐，不重新调用 Embedding。无法找到旧原图时保留空 `content_id` 和来源位置身份，不用占位文字冒充图像指纹。

检索融合、多查询去重和研究证据去重使用 `chunk_id`。回答引用、研究上下文、运行轨迹和前端引用对象传递 `chunk_id`、`content_id`、`asset_ids`。旧历史没有 ID 时仍可显示，不会据此编造内容身份。

## 多模态 Reranker

`MultimodalReranker` 是独立组件，通过注入的 `VisualEvidenceProvider` 解析和读取原图，不依赖 API 层、PDF 解析器或向量模型。

```text
正文/BM25/文本向量 + 图像向量召回
  -> RRF 融合与 chunk_id 去重
  -> 多模态重排：问题 + 候选文字 + 实际原页
  -> 分数汇总排序
  -> 上下文预算组装
  -> 回答与独立证据核验
```

纯文字候选继续使用原文字重排器；只要候选包含视觉页，OCR、图、表、公式、原页图像都读取对应原图。默认最多 20 个候选、每批最多 8 个候选，再按视觉模型的图片数量和上下文预算拆批。同一批的共享原页只上传一次；混合请求里的纯文字批也使用同一个视觉模型评分。

模型必须返回每个给定 `chunk_id` 恰好一次及有限的 0–100 相关性分数；不接受缺失、重复、未知 ID 或无效分数。分数越高越相关，相同分数保留召回顺序。任何批次失败、原图不可用或预算不足时，整次重排回退原召回顺序，不保留部分批次的重排结果。研究轨迹记录重排状态与候选分数。

这是云端视觉大模型评分式重排，不是已训练的跨编码器，也不是校准后的概率。统一评分提示有助于跨批次比较，但质量、批次偏差、延迟与费用仍需在真实论文问题集上评测。

## 配置

复用现有 `.env.vision` 的视觉模型、图片上限与 Token 预算，无新增依赖或额外密钥。视觉阅读与重排组件依赖独立注入的客户端，后续可在装配层替换重排专用模型，不需要改检索或索引模块。图像向量召回仍单独使用 `.env.image_embedding`；视觉模型可读图不代表它能提供图像向量。
