# 多候选证据路径与可重放剪枝 v3

本版本实现可选的多候选回答与独立路径核验。它是可评测的工程增量；不宣称自然语言证据已经获得形式化证明，也不把通用多候选搜索作为新颖性结论。

## 运行流程与边界

1. 继续使用真实 Supervisor → 独立 Researcher 工具循环。
2. Answerer 一次批量提出至多四个候选。一个候选是完整答案及其解释，可有至多三条替代证据路径；每条路径至多十二个步骤，逐项对应原问题的必要关系。
3. 标准库内核针对本次实际输入的证据快照检查授权引用和逐字引文。路径内部是 AND，替代路径是 OR。引文存在只说明来源可以核对，不代表结论已被支持。
4. 独立 Verifier 批量检查未被剪枝的路径，逐项检查实体、地点、时间、单位和桥接关系。其支持与矛盾结论均是模型报告。
5. 只有完整路径得到支持、所有必要关系覆盖、没有阻塞意见或待查问题，才能选择答案。多个不同答案同时得到支持时保留歧义。最终输出仍经现有答案转换流程。

| 状况 | 路径行为 | 候选行为 |
|---|---|---|
| 引用不在本次授权证据中 | 硬剪枝该证明路径 | 保留未知 |
| 非空引文不是对应证据的逐字子串 | 硬剪枝该证明路径 | 保留未知 |
| 缺引文、缺步骤或缺必要关系 | 未知，不硬剪 | 保留未知 |
| 模型认为语义矛盾或实体冲突 | 争议，不硬剪 | 保留争议或未知 |
| 一个路径无效，另一个完整路径受支持 | 使用替代路径 | 可获支持 |
| 所有已知路径无效 | 当前证明不可用 | 不宣称答案本身为假 |

初版硬规则限定为**提交证明的完整性**。它尚不能用确定性算法判定“同名城市是否同一实体”或“出版人角色是否发生冲突”；这些依然交给独立语义核验并允许弃答。后续需要有来源保证的结构化事实与适用条件，才能扩展语义剪枝规则。

## 保留与恢复

四个候选槽位用于整个研究运行。已有未知候选不会被新猜测挤出；模型为同一候选补证据时复用答案与解释。槽位满时，新提议进入轨迹的 overflow_proposals，不能暗中覆盖旧候选。后续轮次旧候选若没有重新提交适用于当前输入的路径，将恢复为未知；旧路径完整保存在历史快照。

`candidates.proposed` 保存本轮实际证据、候选、路径和证书；`candidates.reviewed` 保存独立评审、候选状态及选择结果。它们复用原有独立轨迹记录器，记录故障不阻断业务。图状态保存当前候选、历轮提议快照及选择结果，可随现有检查点恢复。完整工具观察仍不进入父调度上下文。

证书包含规则版本、路径指纹、完整输入证据指纹、出错步骤、引用与作用范围。`replay_certificate` 必须在相同原始路径和相同证据快照上逐字段匹配；证据或路径变动后旧证书失效。有效来源仍不能代替语义蕴含检查。

## 配置与模块

默认配置保持关闭。显式启用时，在个人配置中选择：

```dotenv
AGENTIC_RAG_ENABLED=true
AGENT_EVIDENCE_CONTROL_ENABLED=true
AGENT_EVIDENCE_POLICY_VERSION=v3
```

本次没有修改私人配置或重启业务服务。

应用恢复身份包含 AgentSettings，切换策略会触发原有恢复身份校验；不要用 v3 静默续跑 v1/v2 的中断任务，应以新策略提交新研究。同版本 v3 检查点保留候选与路径快照。既有资料与已保存会话仍按原格式读取。

- `core/evidence_paths.py`：只依赖标准库的路径检查、指纹、证书重放和状态归约。
- `agents/path_contracts.py`：有界生成/核验协议。
- `agents/path_answering.py`：真实图中的批量生成与独立核验。
- `deepsearch_experiments/benchmarks/multihop/pruning_audit.py`：运行完成后的独立审计；不进入生产依赖。
- `scripts/evaluate_multicandidate_paths.py`：冻结、真实推理、分组和成本对照；所有评测调用经过原有预算运行器。

## 评测协议

复用旧 canary 的四道题和各自完整候选文档库，运行相同代码、模型、检索器和预算下的 v2 / v3-shadow / v3。v3-shadow 保留同样的候选与合法性检查，但不从核验输入中跳过失效路径；无效来源仍不能通过最终接受门槛。它是跳过路径这一行为的消融，不是允许无证据回答的基线。

每题预算维持 24 次模型调用、8 次搜索、256000 Token、单次最大输出 8192、上下文 131072、600 秒。生成、核验、格式修复与最终答案转换全部计费；失败和未知用量均保留，不自动重试。提供者未配置可复现随机种子，单次小样本不能识别稳定因果收益。

KABG 题目的标注把新墨西哥州与加利福尼亚州的 Los Alamos 混接，隔离出有效标注指标；同时保留原始四题自动评分供追溯。这个隔离说明不是人工答案判定。运行时不读取答案标注或隔离列表。

误剪指标分别报告：

- **证书重放失败数**：衡量程序是否忠实执行当前规则，不衡量语义正确性。
- **候选文本 EM 代理**：报告沿用字段名 `candidate_oracle_em_proxy`，实际只比较候选完整文本与标注答案的规范化精确匹配。候选可能是完整句，而最终答案另经缩短投影，因此该数值不是严格的 Oracle 上限，可能低于最终 EM；不能用它推断候选是否语义正确。
- **匹配标注候选的全部已知路径被剪风险代理**：以候选 × 轮次为观测单位，仅对存在路径的匹配候选计算；不等于真实误剪率。
- **真实误剪率**：需要独立确认正确的证据路径作为分母；没有这类标签时记录 null，不能报告为 0%。

成功、失败、未知的完整轨迹分别写入新目录；执行状态、内部核验、自动答案得分、人工判定和根因继续分开保存。评测报告以 `output/multicandidate-paths-20261019/summary.json`、`per-case.json` 和 `validation.json` 为准。

执行异常进入 failure；正常弃答、证据不足及被隔离的错误标注进入 unknown；正常作答再按自动答案匹配进入 success/failure。这些分组不代替独立人工判定。

## 独立复核闭环

`scripts/review_multicandidate_paths.py` 导出逐路径复核清单和固定候选输入的剪枝体积对照。后者只统计输入字节数及估算 Token，不冒充实际提供者的总 Token 节省。

将 `review/path-review.jsonl` 复制成另一份审核文件，只填写 `reviewed_path_correct`、`reviewed_prune_error`、`reviewer` 和 `root_cause`；核对路径是否完整回答原问题且由指定证据支持，不以答案字符串匹配代替判断。原清单与原证据禁止覆盖。

```powershell
$env:PYTHONPATH = 'src'
.venv/Scripts/python.exe scripts/review_multicandidate_paths.py --queue output/multicandidate-paths-20261019/review/path-review.jsonl --labels <独立审核副本.jsonl> --output <新的审核统计.json>
```

统计器拒绝修改过的证据、路径和剪枝元数据，拒绝重复审核与不一致标签。真实误剪率定义为“被剪掉的已审核正确路径数 / 全部已审核正确路径数”；同时报告“已审核剪枝中错误剪枝的占比”和审核覆盖率，避免两个分母混用。空分母始终为 null。审核者身份只记录，不由这个离线脚本认证。没有真实独立审核时仍不能声称真实误剪率为零。

复核单位是“题目 × 运行 × 轮次 × 路径”观察；同一路径在多轮出现时分别计数。这是逐次决策误剪率，不是去重后的唯一命题误剪率。

## 本轮实际结果

同一冻结版本、MiMo `mimo-v2.6-pro`、相同原语料与预算完成 4 题 × 3 组共 12 次真实尝试，没有重试。下表正确率排除 KABG 后使用三题，成本则包含全部四题、错误调用及格式修复；提供者用量全部已知。

| 策略 | 有效标注题的最终精确匹配 | 模型调用 | 真实总 Token | 硬剪枝路径 |
|---|---:|---:|---:|---:|
| v2 单草稿基线 | 1/3 | 33 | 126835 | 不适用 |
| v3-shadow 多候选、不跳过失效路径 | 2/3 | 30 | 113337 | 0 |
| v3 多候选、启用硬剪枝 | 2/3 | 32 | 130999 | 0 |

实际共记录 13 条“路径 × 轮次”观察，证书全部可重放，没有无效引文或越界引用触发硬剪枝。固定同一候选输入的剪枝字节节省与估算 Token 节省均为零。真实误剪率为 null：既未触发实际剪枝，也没有独立审核的正确路径标签。不能把“零次剪枝”写成“零误剪率”。可触发剪枝、保留未知、替代路径、失效证书等分支已由离线契约与真实图测试覆盖，但这不等于真实模型上的语义剪枝效果验证。

v3 本次总 Token 比 v2 高 3.28%，比 shadow 高 15.58%。四题按历史结果挑选、每组只有一次随机运行；v2 与 v3 还存在评审协议和假设更新差异。正确率差异不能归因为硬剪枝收益，也不能外推到总体。当前不建议据此默认启用 v3。

逐题观察：

- **KABG**：三组均未给出县名，避免跟随错误的跨州标注。v3 保留四个未知候选，但其中出现解释相近、措辞不同的候选，占满槽位后另有一项提议进入 overflow。它还发生 Answerer/Verifier 各一次 JSON 格式修复；该题用量为 74902 Token，基线为 45582。成本主要增加在候选生成和核验，不能归咎于未触发的剪枝。
- **The North Star**：两组多候选仍因角色/证据关系未解决而弃答，没有解决该 Badcase。v2 在核验输出达到 8192 上限后截断，作为执行失败单独保留，已知用量 25625 Token。
- **同国籍判断**：两组多候选均输出 yes；v2 已生成加拿大相关结论，但假设更新引文未通过逐字校验而弃答。这是本轮观测，不证明结果稳定复现。
- **成功对照**：三组均输出 Michel Le Denmat，保持正确。

后续应先解决候选身份与自由措辞造成的重复、对相同未知状态重复起草的成本，再建立实体身份/关系约束及正确路径的独立审核集；不能用收紧未知候选删除规则换取表面节省。

回归结果为 **931 passed, 14 skipped**。201 个模块、477 条依赖边，无循环或越界依赖。最初一次全套测试遇到系统临时目录的 PDF 清理权限错误，保留日志后改用项目内 TEMP/TMP 完整重跑通过。233 个历史文件哈希保持不变。12 条新轨迹分为 5 条 success、1 条 failure、6 条 unknown；这些分类均非人工正确性标签。
