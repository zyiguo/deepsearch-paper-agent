# ADR-0003：Embedding 与对话 LLM 配置分离

## 状态

Amended（2026-09-12）。原决策「本地 BGE-M3」**未采用**；当前实现为 OpenAI 兼容云端 Embedding API（默认 `text-embedding-v4`，1024 维），与对话 LLM 使用独立的 `.env` / `.env.embedding`。

## 背景

用户希望获得云端模型的回答质量，同时控制配置与成本，并将 Embedding 凭证与对话模型凭证分离，便于替换服务商。

## 决策

- **对话 LLM**：云端 OpenAI 兼容接口，只接收问题、必要会话上下文和检索出的少量证据片段。
- **Embedding**：同样使用 OpenAI 兼容接口（`EMBEDDING_*` 配置），独立于 `LLM_*`。全库 Chunk 文本会发送至 Embedding 服务商。
- 演示模式将 `*_BACKEND=demo`，不访问网络。

## 后果

- 优点：无本地 GPU/模型缓存负担；凭证与模型可独立更换；启动路径简单。
- 缺点：**索引阶段会上传全文**，隐私与成本依赖服务商；断网或密钥错误时无法建索引（启动失败而非静默降级）。
- 替代方案：本地 BGE-M3 可避免全文上传，但需模型下载与运行时管理，留待后续 ADR。
