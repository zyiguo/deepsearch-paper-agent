# ADR-0008：可选 Redis 缓存与运行保障

状态：Accepted。补充 ADR-0006，不替换现有持久化边界。

项目需要减少重复模型调用、限制短时间请求压力，并提供可追踪的部署运行方式。现有索引位于 API 内存并写入 JSON，后台处理直接访问应用状态，因此独立 Worker 无法直接复用此运行模型。

决定：Redis 作为可丢弃的文本 Embedding 缓存与限流计数器，默认可关闭。缓存失败绕过，限流失败回退有界本地窗口。新增请求编号、元数据访问日志和存活/就绪检查。提供非 root 单进程 API 容器与仅回环开放的 Redis Compose 配置。会话 SQLite、文献文件和索引 JSON 保持现有职责。

替代方案：仅加 Redis 缓存改动较少，但不能提供请求保护和部署诊断；直接上 Celery/PostgreSQL 需要同时解决索引跨进程可见、任务幂等与权限模型，超出这一基础模块的闭环。

结果：已有本地流程可继续运行；开启缓存后真实导入与查询路径受益。Redis 故障无需阻断问答，但可能增加模型调用；本地回退不构成精确配额。仍只支持单 API 进程和单用户信任边界，不宣称高可用、多租户或生产环境验收完成。
