# ADR-0014：部署级运行治理、成本预占与资源保护

## 状态

Accepted（2026-10-20），补充 ADR-0010/0012/0013。仍为单 API 进程、模块化单体。

## 背景

每个工作空间各自限流和持有线程，不能限制同一用户跨空间的费用，也不能限制整个部署的供应商并发。HTTP 200/SSE error 必须与正常研究完成分开统计。模型用量缺失或执行中断不能当成零费用。

## 决策

1. 组合根创建一个 Governance 服务并注入所有空间；核心 ContextVar 传递认证用户、空间、原研究运行及工具操作身份。线程显式复制上下文，研究恢复沿用持久请求中的发起人。
2. 模型 HTTP、文本和图像向量的实际适配器计量；缓存命中和工具结果重放不重新预占。OCR/视觉沿用模型 HTTP 边界。
3. 控制平面 SQLite 在事务中同时检查用户和空间额度。保留 reserved/running/settled/unknown/released，运行中断不隐式释放未知费用。业务 PostgreSQL schema 不变；控制文件进入已有停写备份根目录。
4. 使用可配置整数成本点，供应商 Token 用量确定时按记录中的换算率结算；价格与汇率不写死。没有用量的调用继续占额度，人工核对有独立审计。
5. 全局/空间/用户三级非阻塞并发准入覆盖研究、入库队列和模型/向量调用。过载显式拒绝，不建立无界队列。
6. 指标仅用有限的业务维度，提供受保护的 Prometheus 文本出口。告警条件在本地周期评估并保存 pending/firing/resolved 状态，输出结构化日志；不发送外部通知。

## 取舍

- SQLite 而非 Redis 作为额度真相，能在缓存故障和重启后保留未知费用；每次调用增加事务成本。
- 使用部署级并发控制而非立即拆 Worker，保留当前索引所有权和检查点机制；不提供多副本协调或全局硬内存上限。
- 不把预计用量当作真实账单。预占不足会记录实际超额并告警，后续准入依据已结算/冻结总额，不反向修改供应商报告。
- 进程指标和滚动窗口会在重启后重置，长期监控需要外部采集。额度、核对审计和告警状态持久化；未知工具积压通过只读账本扫描覆盖未加载空间。
- 第三方 MCP 费用尚无可信计量协议，不纳入自动费用结算；其未知操作仍由原工具账本保护。

## 替代方案

每个空间独立计数不能满足跨空间用户额度；只用 Redis 无法把缓存降级与费用丢失分开；引入分布式队列和共享索引发布会超出当前部署边界。
