# 本地文献问答协调

用户已确认：增加 Supervisor 动态规划和调度，由 LangGraph 条件边协调。
入口 Supervisor；Researcher 完成后回 Supervisor；Answerer 每次输出必须经过 Verifier 后回 Supervisor。
Supervisor 可以选择 research、draft、revise、finish、stop，但不能绕过引用和核验检查发布草稿。
它维护最多八个子问题及 pending/in_progress/done/blocked 状态，结合证据与评审意见重新规划。
任务完成状态只用于调度，不作为事实已验证的依据。检索角色收到任务及指令，修订角色收到旧稿与评审意见。
不做评测平台、运行轨迹、预算模块、联网或长报告。保留现有接口及会话存储。

真实聊天模型启用图流程，demo 保持旧演示。角色共享现有 LLMClient。
Researcher 生成最多三个查询，调用现有混合检索，追加去重证据并保持编号稳定。
Answerer 输出结构化结论与引用；Verifier 独立检查支持关系，给出补查查询。
引用范围由程序强制验证。最终只返回通过核验的结论及实际引用片段，重编连续编号。
首次检索后最多补查两次，最多三轮草稿核验和八次调度，防止无限循环；仍不足则保留本轮已核验结论并说明限制。
格式无效安全拒答；服务异常沿用现有 API 错误处理。不保存中间状态、不配置 checkpointer。

这是受约束动态调度的四个模型角色，不是开放式自主多智能体系统。
同一个模型自检仍可能出错，不声称保证事实正确。多次串行调用会增加响应时间。
现有前端超时不因本次变更自动扩大；长请求可能需要后续独立处理。

实现验收：支持结论、非法引用、补查后修正、轮次终止、格式异常、旧接口兼容。
这些是软件行为测试，不是用户暂缓的问答质量评测。
