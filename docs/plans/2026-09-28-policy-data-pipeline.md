# 搜索策略轨迹与后训练数据管线

## 目标与边界

把搜索协议、轨迹存储、审核及数据导出放入独立 `search_policy` 包，仅依赖 Python 标准库，不导入 RAG、LangGraph、FastAPI、Torch 或云端 SDK。RAG 仅通过可选 recorder/observer 接口发布事件，桥接层负责绑定运行上下文。不开启云端、不评价真实模型效果、不自动训练。

## 实施顺序

1. 抽出搜索动作协议及模型客户端接口，保留旧导入兼容入口。
2. 实现版本化 SQLite 事件日志：请求独立 run_id、顺序号、时间、内容哈希、状态；逐事件提交，崩溃留下 running 轨迹；线程间不共享连接。
3. 用适配器记录策略请求/原始输出/解析状态、实际查询来源、检索候选及重排结果、角色输入输出、核验和最终答案。记录失败不能改变问答结果，不记录密钥或异常正文。
4. 实现 CLI：校验与导出原始轨迹、生成待审核样本、根据独立审核文件导出 action-SFT train/val 数据及哈希清单。未知标签不自动变成正例；只导出实际执行成功的 search 动作。
5. 按问题及会话连通分组切分，去重、拒绝冲突标签、拒绝残缺或损坏轨迹。提供可离线运行的样例与测试。

## 训练语义

第一版产出 `messages + text` 的单步 search 决策样本，可接后训练项目的 `encode_step(messages, text, tokenizer, max_length)`。不伪造完整 search/answer 轨迹，不将 RAG 回答转换成训练模型的 answer，也不将 verifier 判定当作奖励。已有训练入口要求完整问题/答案/动作回放，因此不能直接把本导出文件当其原始数据包使用；需要单步 SFT reader，文档给出对接说明。

## 验收

- 无云端调用；独立包可在没有 RAG 依赖时导入和运行 CLI。
- 并发请求不串轨迹；策略失败、检索失败、格式失败、写盘失败有可诊断状态。
- 精确保留策略实际输入与原始输出；检索观察不能冒充模型生成 token。
- 原 RAG 默认关闭记录时行为不变，开启记录时返回结果不变。
- 审核绑定样本内容哈希；未审核、拒绝、回退、失败及残缺轨迹不进入 SFT。
- 导出可重复，无问题或会话跨 train/val；内容与文件哈希可复查。
