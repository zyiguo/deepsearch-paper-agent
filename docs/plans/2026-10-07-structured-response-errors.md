# 结构化响应与错误记录修复

## 目标与范围

修复首轮云端验收暴露的 JSON 包装兼容性和模型错误信息缺失问题。保留原始实验，不改变预算、提示词、MiMo 思考配置或评分标准；不自动重试，不发起收费重评测。

## 设计选择

- 采用本地、确定性的单 JSON 对象提取，拒绝有歧义或非法的结果。相较强制云端 JSON 模式，不改变当前 MiMo 思考配置；相较模型修复调用，不引入额外费用、调用次数和生成不确定性。
- JSON 包装提取与业务校验分离。前者只剥离明确的代码块/说明文字，后者继续验证布尔类型、依赖索引、拓扑排序与无环性。
- 模型网关提供白名单错误码和数值元数据，评测 runtime 负责费用对账，runner 负责持久化。错误文本和上游原始正文不进入诊断记录。

## 实施步骤

1. 新增 `benchmarks/multihop/structured.py`，覆盖纯 JSON、单代码块、说明包装、重复键、多对象、非法数值与深度/大小限制。
2. 更新 `baselines.py`，保留业务校验，在 trace 记录包装类型及解析错误，在结果记录失败阶段与失败码；标记 `single-json-object-envelope-v2`。
3. 更新 `llm_gateway.py` 的 `ModelServiceError`，区分超时、连接、鉴权、权限、限流、服务端错误、拒绝、非 JSON、响应结构异常、空响应、截断和内容过滤。
4. 更新 runtime/runner，记录错误类别、服务端状态、finish reason、单次耗时和可用 usage。缺失总 usage 仍为 null，失败题仍为 0 分。
5. 用 mock transport 测试同步及可取消异步请求；回放上一轮 5 个失败响应的解析和依赖图校验；验证历史产物哈希与离线评分不变。
6. 完成全量回归及修复说明。新云端实验必须使用新的运行目录与代码身份。

## 不包含

不修复检索/推理策略，不增加 IRCoT 时限，不修改历史 badcase 标签，不推测旧模型错误的具体原因，不将离线解析回放作为新 EM/F1。
