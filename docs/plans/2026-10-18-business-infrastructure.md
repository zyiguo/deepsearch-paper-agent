# Redis 与运行基础设施实施计划

目标：在现有本地资料助手上接入实际可用的缓存、流量保护、请求追踪和部署能力。

架构：Redis 是可丢弃的向量缓存与限流计数器；SQLite、原始文件和 JSON 索引继续作为持久数据来源。保留单进程索引所有权，避免独立 Worker 更新后 API 内存索引过期。

1. 新建 infrastructure.py：独立配置、短超时连接池、故障冷却、Embedding 缓存、原子 Redis 限流与有界本地回退。
2. 新建 operations.py：纯 ASGI 请求编号和元数据访问日志；新增存活与就绪端点，兼容 SSE。
3. 在 api.py 生命周期中创建并关闭资源，将缓存包装器接入现有真实 Embedding 客户端。显式测试配置不读取开发者环境。
4. 增加可选依赖、配置模板、Dockerfile、Compose 和运行文档。不读取或复制用户密钥到镜像。
5. 验证缓存复用、模型隔离、损坏值、服务故障回退、冷却恢复、并发限流、过期窗口、请求编号及 API 回归。若 Docker 引擎可用，再验证真实 Redis；如不可用则保留独立集成测试与明确验收边界。

暂不加入 Celery/PostgreSQL：独立任务队列需要先将索引发布与加载改为跨进程可见，并定义幂等任务、租约和计费重试规则；多租户部署需要认证与资料权限模型。
