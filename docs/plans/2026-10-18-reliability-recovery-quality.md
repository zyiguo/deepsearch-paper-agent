# 任务可靠性、数据恢复与质量闭环实施计划

**Goal:** 在现有单 API、SQLite/PostgreSQL、独立轨迹架构上，实现任务幂等与安全恢复、可验证的离线备份还原、人工质量审核到回归关闭的闭环。

**Architecture:** 任务状态与答案仍由现有业务存储维护；增加条件状态转换、保存结果核对和脱敏执行元数据，不创建另一套队列或改变数据库版本。应用生命周期与维护工具共用进程文件锁；维护适配器打包 PostgreSQL 逻辑备份和完整业务文件，只向新隔离环境还原。质量冻结、审核与对比位于独立标准库轨迹包，生产问答不导入评测运行器。

**Tech Stack:** Python、PostgreSQL、SQLite、FastAPI/SSE、标准库文件锁/哈希/JSON、官方 PostgreSQL 容器工具。

## 1. 任务可靠性

- 修改 `application/session_runs.py`、会话/运行的 SQLite 与 PostgreSQL 适配器、Web 会话路由及装配。
- 普通和流式会话共用持久任务记录。支持可选 Idempotency-Key，相同请求重放已提交答案，不因重复请求再次调用模型；不同请求复用键拒绝。
- 条件状态转换防止取消/完成被迟到进度覆盖；执行元数据记录尝试次数与安全错误码。
- 恢复前核对模型/预算/资料/记忆身份；已提交轮次优先修复完成状态；缺少检查点明确拒绝自动重跑。异常终态写入失败仍结束 SSE，保留未知而非伪造成功。
- 测试覆盖并发键、重复提交、取消竞态、状态写入失败、恢复身份变化、已保存答案恢复和断连。

## 2. 数据恢复

- 新增部署文件锁，在真实 API 根生命周期及维护写入口互斥。离线备份拒绝与本应用并行写入。
- 新增维护 CLI/适配器：新目录备份、清单校验、向新隔离容器和新目录还原演练。打包数据库、账号空间、旧本地资料和运行文件，配置只保留身份摘要，不导出模型密钥；登录会话在演练恢复后撤销。
- 不覆盖源目录、现有数据库/卷或已有报告；拒绝符号链接、路径逃逸、损坏清单；失败保留失败报告，清理仅限本轮创建的隔离资源。
- 在当前真实 PostgreSQL 及迁移后的业务数据上执行一次离线备份和完整还原演练，核对全部业务表和文件哈希；随后恢复原服务。

## 3. 质量闭环

- 新增 `deepsearch_tracing/quality.py`：冻结可校验轨迹快照、独立人工审核、按 case_id 对比审核版本。
- 执行结果/内部核验/人工正确性/根因分别统计；未知不进入正确率分母，明确审核覆盖率。
- 错例要有复现 case_id、期望依据和根因；只有同一输入/语料/模型预算条件下人工复核正确，才能输出已解决；缺评、身份变化、无改善保持待验证。
- 文件独占创建，审核关联原运行指纹和快照摘要；原轨迹不回写，记录故障不阻断生产。
- 合成闭环验收明确标记，真实历史缺少轨迹或人工标签保持未知，不伪造质量提升。

## 4. 验收及交付

- 分阶段专项测试、完整后端回归、架构审计；真实 PostgreSQL 与恢复演练独立记录。
- 新增 ADR、操作说明及验证记录，解释运行结果恢复和数据库灾难恢复的区别。
- 当前管理员账号与历史资料保留；服务暂停只在备份/重启期间，不进行付费云模型评测，不提交或发布代码。
