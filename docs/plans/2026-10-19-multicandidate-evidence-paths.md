# 多候选证据路径与可重放剪枝

用户已授权实现和现有 Badcase 对照评测。复用当前工作区、真实父子 Agent 和预算运行器，保持默认策略与用户数据不变。

## 实施边界

1. 标准库证据路径内核：候选内路径 OR，路径内证据步骤 AND。只有不在授权证据中的引用、与当前证据不符的非空逐字引文能够形成硬剪枝证书。缺引文、缺关系、模型认为矛盾均保留未知，不把引文存在当作语义支持。初版不宣称能形式化证明自然语言事实冲突。
2. v3 可选策略：一次批量产生至多四个候选、每个至多三条路径；一次独立批量核验。保留历轮候选快照；被剪的是具体证明路径，所有路径失效也不删除候选答案。更新证据后重新检查。v3-shadow 执行相同检查但不跳过失效路径，作为剪枝消融。
3. 全部模型调用经过现有预算接口，独立核验只接收授权证据与候选，不接收子循环原始观察。完整候选、证据快照、证书与选择事件进入原有轨迹。
4. 单元和真实图测试：未知保留、替代路径、恶意/越界引用、引文变动、证书重放、核验漏项、多个不同受支持答案的歧义、检查点恢复、预算和旧版回归。
5. 冻结代码后，以旧 canary 的四题（含三个历史 Badcase、一个成功对照）运行同预算 v2 / v3-shadow / v3，使用原完整候选语料。KABG 的跨州错误标注隔离，不用它指导运行时决策。
6. 输出每题候选覆盖、剪枝数、正确候选保留代理指标、独立真实误剪率的未知范围、最终 EM/F1、所有尝试的真实 Token 用量与未知用量计数。无合格分母时指标为 null。评测样本按历史结果挑选，不能外推总体准确率。

## 验收

针对性测试 → 全套测试/架构检查 → 冻结代码 → 真实推理 → 轨迹审计与成本对照 → 历史文件哈希校验 → 文档与验证记录。失败不自动重试，所有输出使用新目录且禁止覆盖。
