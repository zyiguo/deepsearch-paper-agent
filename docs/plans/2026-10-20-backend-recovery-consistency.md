# 后端恢复与入库一致性实施计划

## 目标与范围

延续单 API 模块化单体，实现三个已确认缺口：记忆工具恢复授权与确定未执行分类、未知调用的审计核对、入库步骤持久化及一致性修复。保留旧索引、检查点、会话和账本，不改写历史实验结果，不自动发布 GitHub。

## 实施顺序

1. 增加明确的未执行异常与账本终态；缓存读取恢复记忆授权，缓存写入撤销授权。未知网络和磁盘结果仍保留未知。
2. 在会话运行服务中加入核对用例与 HTTP 入口。只允许暂停中的原任务、同工作区授权用户核对；记录操作者、证明引用和结果摘要，原任务继续使用既有恢复入口。查询、超时和未经核实的结果均不自动重试。
3. 将入库中间产物与步骤记录独立保存，以资料和模型身份隔离；复用已保存的解析、文本向量和图像向量。索引发布与 ready 元数据之间发生中断时，通过源级指纹核对和修复。付费步骤无确认产物时暂停，显式确认后才允许重做。
4. 为上述边界增加故障注入、权限、并发和兼容性测试，运行后端回归及架构约束检查。更新设计、使用方法和验证记录。

## 验收

- 新绑定记忆对象可通过已确认读取的重放进行一次正确写入；过期内容不获得有效写入权限。
- 确定未执行的失败不会进入 unknown；结果不确定的付费和副作用调用仍禁止自动重发。
- 核对操作有持久审计，禁止跨会话、跨工作区和运行中核对；核对后的原任务可恢复且不重发已确认工具。
- 元数据落盘失败后的入库恢复不重复解析、视觉分析或向量生成；未知付费步骤不被静默重复。
- 旧格式继续读取，检查与修复有明确边界，原始文件不被清理。
