## 日志内容

每次不完整回答输出一条 WARNING JSON 摘要，不新建日志文件或上传远程平台。字段只有随机 diagnostic_id、固定原因代码、片段/草稿/核验通过/待查查询/问题/漏项数量，以及检索轮数 rounds、核验轮数 reviews、调度数 dispatches 和 verified 状态。

不会记录问题、片段、答案、模型评审原文、路径、密钥、HTTP 请求头或思考内容。格式校验失败时拿不到完整终态，计数为 null（未知），不是零。诊断只涵盖工作流正常结束的不完整回答及 schema 校验失败；连接失败、进程被中断等仍看原错误提示。

| reason | 含义 |
| --- | --- |
| finish_before_verification | 未完成一次核验就结束 |
| stopped_after_research | 已核验过，但补查后清空核验结果并结束 |
| empty_draft | 核验时草稿为空 |
| no_supported_claims | 有草稿，但没有可发布的通过核验结论 |
| supervisor_stop | 模型主动选择 stop；结合计数判断停在哪一步 |
| dispatch_limit / research_limit / review_limit | 达到对应次数上限 |
| no_evidence_for_draft / revise_without_draft | 请求的动作缺少必要输入 |
| partial_answer | 仍存在未通过结论、待查问题或漏项 |
| schema_validation_failed | 模型结构化输出未通过校验 |

这些是程序停止条件，不是模型语义判断错误的最终根因。比如 no_supported_claims 仍可能来自模型否决或引用编号校验失败，需要根据摘要再决定最小排查范围。
