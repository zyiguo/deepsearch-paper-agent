# 结构化记忆与压缩摘要验收

## 本次实现

沿用 SQLite，新增 session_memories 表，不修改已有问答表内容，不引入向量记忆库或新模型服务。

- 结构化记忆：研究目标、语言/回答风格、文献 ID、讨论对象、待解决问题。
- 压缩摘要：第 7 轮成功保存后触发，压缩前 4 轮，保留最近 3 轮原文；之后累计新增 3 轮再更新。每批只尝试一次。
- 最近原文：只从当前文献范围且最后一次清空后的历史取最近 3 轮。
- 摘要、研究目标与实体作为 memory_context 传给图角色，明确不是证据；引用仍来自本次限定文献检索。
- 模型只能更新 summary、active_entities、open_questions，不能修改文献范围或用户设置。结构化输出不合法则拒绝写入。
- revision 乐观锁：切换范围、清空或编辑发生后，旧压缩结果无法覆盖新版本。

讨论对象和待解决问题第一版为受数量/长度限制的字符串列表，归属于当前文献范围；summary_through_turn 记录摘要覆盖的最后一轮 ID。尚未实现逐条实体到原文的证据映射，不得把这些条目作为论文事实。

## 界面

会话标题下“记忆”默认折叠。展开可编辑研究目标、语言、风格，查看摘要、讨论对象、待解决问题并清空记忆。

左侧改选文献会更新当前会话范围并清空范围相关记忆。刷新或切换会话会恢复该会话的文献选择；无效/未入库文献仍不能参与检索。清空全部文献后不允许提问。

清空记忆保留研究目标、偏好、文献选择和可查看的历史，但清空前历史不再自动注入新问题。删除会话会一并删除其记忆。

旧会话第一次使用记忆功能时，历史的文献范围无法可靠判断，因此旧历史保持可查看但不自动纳入新记忆；从绑定范围后的新问答开始积累。

## 压缩费用与失败边界

真实调用未由助手执行。达到阈值后，会额外调用一次已配置聊天模型并显示“正在整理会话记忆”。答案先保存，再进行压缩；压缩失败不撤销问答，不重试同一批，界面显示压缩失败。后续又新增 3 轮时可尝试更新新的批次。

压缩输入不含引用正文，每轮问题最多 2000 字符、历史答案最多 3000 字符，总输入超过 24000 字符时本地拒绝压缩，不调用模型。摘要最多 2000 字符，实体和问题各最多 20 项、每项最多 200 字符。因此摘要不保证保留历史的所有细节。

分批更新间隔中，较早但尚未压缩的轮次仍保存在会话历史，只自动注入最近 3 轮；第一版没有对任意历史问题的搜索功能。需要精确细节仍应从所选 PDF 检索，不依靠摘要回答。

压缩发生在答复保存之后、流式 done 之前，所以达到阈值的轮次会额外等待一次模型请求；断线后先刷新会话核对，避免重复发送。

## 先做无额外模型调用的界面验收

1. 新建会话，只勾选测试 PDF。展开记忆，设置研究目标并保存。
2. 刷新页面：目标、偏好、文献选择应恢复。
3. 改选文献：旧摘要、实体和待解决问题清空，研究目标与偏好保留。
4. 清空记忆：历史问答仍显示，新的上下文从清空后开始。

## 可选真实压缩验收（会计费）

在同一范围累计 7 轮问答后检查摘要已更新或明确标记失败。摘要只描述研究主题和待解决问题；不要把“历史助手说过什么”当作论文证据。第 8、9 轮不应再压缩，第 10 轮触发下一批。

不建议为了覆盖所有失败分支反复调用模型；过期写入、失败不重试等已用本地 fake client 检查。
