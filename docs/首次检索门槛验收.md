# 首次检索门槛修复

用户日志显示首次 Supervisor 调度即 stop，rounds=0、evidence_count=0。这不是检索失败，而是尚未检索就退出。

本次改动：在 ResearchWorkflow.supervise 中，rounds=0 时将 stop/finish 改为 research，并覆盖停止指令为围绕原问题检索。完成第一次检索后仍允许停止；不绕过核验、不改重试次数，也不修改模型超时。

离线测试先复现了与用户相同的 stop 日志及零检索次数，再验证首次 stop/finish 均执行一次检索并可完成核验回答；空检索后仍允许正常停止。

## 由你执行一次真实验收

在原后端终端 Ctrl+C，然后执行：

```powershell
Set-Location '.'
& .\.venv\Scripts\python.exe -B -m uvicorn deepsearch_agent.api:app --host 127.0.0.1 --port 8000
```

刷新前端，新建会话并发送一次原 AX-247 四属性问题。无需重新上传 PDF。应进入检索阶段，不能再出现第一次调度即 supervisor_stop 且 rounds=0 的正常终态。

若仍失败，发回阶段、最终提示及 research_failure 行，避免连续重发。模型连接或格式异常仍可能在检索前失败，本修复不保证外部服务可用；两分钟等待原因尚未确认，也不承诺本次会缩短首次模型请求耗时。

本轮没有调用真实模型，真实验收留给用户执行。
